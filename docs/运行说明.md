# 运行说明

## 目录

```
school_timetable/
├── backend/    Django + DRF + JWT
├── frontend/   Vue3 + Vite + Naive UI
├── docs/       设计与决策文档
└── files/      原始 Excel（课表模板 / 课时记录）
```

## 后端

```bash
cd backend
# 依赖已装在 .venv（uv 管理）；如需重建：
uv pip install --python .venv/bin/python -e .

# 迁移
.venv/bin/python manage.py migrate

# 创建超级管理员
.venv/bin/python manage.py createsuperuser

# 从 Excel 导入初始数据（可选，用于试用）
.venv/bin/python manage.py import_initial
#   可选参数：--week-start 2026-09-07  --dir /path/to/files

# 启动（注意端口 8000 可能被其他项目占用，这里用 8001）
.venv/bin/python manage.py runserver 127.0.0.1:8001

# 测试
.venv/bin/python manage.py test timetable
```

API 文档（Swagger）：http://127.0.0.1:8001/api/docs/

## 前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5273 （代理到后端 8001）
npm run build      # 类型检查 + 构建
```

> 开发端口与代理目标见 `frontend/vite.config.ts`。

## 主要页面

- 排课：周网格，点格编辑；一键排课 / 存为模板 / 复制单日 / 班级同步 / 清空
- 模板管理：模板列表（新建空白 / 从某周生成 / 复制 / 重命名 / 设默认 / 删除）+ 内容网格逐格编辑（只编学科，即时保存）+ 应用模板到某周
- 查看：班级课表、教师课表（含冲突提示）
- 报表：教师课时明细、教师课时汇总（各时间段一列 × 权重 + 合计）
- 基础资料：学科 / 教师 / 班级 / 时间段 / 学期 / 任课关系
- 设置：锁定设置（锁定至某日，保护历史不被误改）

## 平板适配

- 侧边栏可折叠（窄屏默认折叠为图标栏），头部左侧按钮切换。
- 周网格自适应铺满宽度，一周（7 天）在平板竖屏/横屏下均无需横向滚动；班级/教师课表若查询区间超过一周则保持最小列宽并横向滚动。
- 选学科/教师改为"点开即选"：学科以按钮网格铺出，教师为可滚动列表（同当前学科的教师排在最前，并标注各自学科）；保留"保存"按钮以便同时调整。

## 服务器部署（宝塔 + Nginx 子路径）

参照 `personal_finance` 的部署方式：机密集中在 `/opt/zhangyahan/school-timetable.env`，项目内提供 `deploy.sh`。

### 1. 环境文件

```bash
cp school-timetable.env.example /opt/zhangyahan/school-timetable.env
vim /opt/zhangyahan/school-timetable.env   # 填 SECRET_KEY / ALLOWED_HOSTS / CORS_ALLOWED_ORIGINS / VITE_BASE / VITE_API_BASE_URL
```

### 2. 部署

```bash
cd /opt/zhangyahan/school-timetable
./deploy.sh
```

`deploy.sh` 会：`git pull` → 由 `backend/.env.production.template` 生成 `.env.production` → `uv sync` → `migrate` → 由 `frontend/.env.production.template` 生成 `.env.production` → `npm install` → `npm run build-prod` → 把 `dist/` 复制到网站根目录。之后在宝塔面板重启后端项目即可。

### 3. Nginx（在现有站点 `xph.silyahuukou.cn` 的配置中追加）

```nginx
location /school-timetable/ {
    try_files $uri /school-timetable/index.html;
}
location /school-timetable/api/ {
    proxy_pass http://127.0.0.1:8014/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_redirect off;
}
```

- 前端构建产物目录：`/www/wwwroot/xph.silyahuukou.cn/school-timetable/`
- 后端：宝塔「Python 项目」新建，gunicorn 模式，指向 `backend/`，端口建议 `8014`（`personal_finance` 占用了 8013）。
- `VITE_BASE` 必须与 Nginx 子路径一致（`/school-timetable/`），而 `VITE_API_BASE_URL` 与上面 proxy 的路径一致。

> **运行用户**：宝塔项目 gunicorn 的 `user`（默认 `www`）需能访问 Python 解释器与读写 `db.sqlite3`/`logs`。
> 因此 Python 装在共享目录 `/opt/uv-python`（`UV_PYTHON_INSTALL_DIR`），且 `deploy.sh` 会把 `backend/` 归属设为 `BACKEND_USER`（默认 `www`）。若宝塔项目以 root 运行，可设 `BACKEND_USER=root`。

### 环境变量（`.env.production` 由模板生成）

| 变量 | 说明 |
|---|---|
| `SECRET_KEY` | Django 密钥 |
| `ALLOWED_HOSTS` | 逗号分隔 |
| `CORS_ALLOWED_ORIGINS` | 同域代理时可不依赖 |
| `VITE_BASE` | 前端子路径，如 `/school-timetable/` |
| `VITE_API_BASE_URL` | 如 `http://xph.silyahuukou.cn/school-timetable/api` |
