# 排课系统 · 设计与决策文档

> 本文档整理调研、讨论结论与最终实施方案，作为开发依据。
> 最近更新：2026-09-20

## 1. 项目背景

绛县中学高一（1）部共 **9 个班（2601–2609）**、**40 名教师**。目前已确定一份周课表模板，需要构建一个前后端分离系统，支持：

- 排课（含批量调整、模板）
- 按时间段查看班级课表
- 教师个人课程明细
- 教师课时汇总

历史记录需要保留（周表 / 月表 / 年表汇总）。

## 2. 数据摸底（源文件）

| 文件 | 内容 |
|---|---|
| `files/高一课程表9月定.xlsx` | **课表模板**（9 个班的周课表） |
| `files/2026-2027学年第一学期高一（1）部课时记录.xlsx` | 教师课时统计表（人工统计，仅示意） |
| `files/课程表.xls` | 源数据/旧版（内容与上表一致） |

### 2.1 基本事实

- 1 个部，9 个班：2601–2609，每班有班主任。
- 40 名教师，每人归属 1 个学科。
- 13 个学科：语/数/英/物/化/生/政/历/地/音/体/舞/美。
- 每班每周各科节数完全相同（模板平衡性）：
  语 9 / 数 9 / 英 9 / 物 6 / 化 5 / 生 4 / 政 4 / 历 5 / 地 4 / 音 1 / 体 2 / 舞 1 / 美 1，合计 **60 节/班**。
- 时间段（行）结构：`早读`、`一~八`、`晚一~晚四`，另有 `早饭 / 早自主 / 午休 / 晚饭` 等展示行。
- 实测：`早自主`、`晚四`、周末两列均为空；`周清` 只是周日早饭行的标记，无学科无教师。

### 2.2 教师任课来源

每班底部有一行按固定学科顺序排列的 13 个教师姓名，即 `班级 × 学科 → 教师` 映射。
据此把课表还原为教师课时，结果与人工表逐格吻合（差异处即人工笔误，如个别教师"课四"手数错误）。

### 2.3 人工统计口径

`早读`、`课四`、`课八` 单列；`课时 = 一+二+三+五+六+七`；`晚自习` 另计；
`合计 = 早读 + 课四 + 课八 + 课时 + 晚自习`（当前系数均为 1）。

## 3. 关键设计结论（讨论产出）

1. **模板是生成器，不是历史载体**：模板只定义"班级×星期×时间段→学科"的通用模式，用于批量生成。历史由实际课程记录保存。
2. **实际课程记录是历史唯一真相**：每条记录快照当时的班级/学科/教师，因此历史不依赖模板或任课关系的版本。
3. **任课关系只存当前默认值**：仅用于排课时自动带出默认老师；不设生效日期版本。想看历史必须先生成过对应周的记录。
4. **不设持久"日期覆盖规则"**：放假/换天/挖洞都做成对实际课程记录的批量操作，避免两套真相。
5. **教师与学科分开**：学科挂在实际记录/任课关系上；教师表上的学科只作默认提示（一人一科，可后期修改）。
6. **模板保存规则**：所选范围必须是完整周一~周日；保存全体班级、7 天全量；未排格子存空，不校验完整性。不允许按班存模板。
7. **一键排课**：按整周生成；默认整周覆盖（带确认），另提供"仅补空"。
8. **换老师**：改任课关系 → 重排未来未锁定的周（覆盖）。不做专用批量换老师工具。
9. **锁定**：全局"锁定至某日"；该日及之前记录不可改删。批量操作（一键排课、清空等）若范围与锁定区间有交集，**整体拒绝执行**，绝不半覆盖。
10. **汇总**：每个时间段各占一列（次数 × 权重）+ 合计列，可在此基础手动加改，不做分组合并。
11. **权重**：按时间段配置，默认 1；时间段只表示排序，不绑定具体时刻。**每条课程记录在写入时把当时权重快照到 `CourseSession.weight`**，汇总按快照求和——因此改时间段权重只影响以后新写入/重排的记录，历史不变。
12. **时间段变更**：不需要"时间段模板/版本"；模板永远按当前启用时间段与排序解释。停用某时间段时，**自动删除它在所有模板中的条目**（该行消失）；重新启用后该行为空待填。历史记录不受影响（仍挂在旧时间段上）。
13. **单管理员**：一个超级管理员拥有全部权限。不做角色 RBAC、不开放注册、无 JWT 黑名单。后续如有需要再扩展教师只读角色。
14. **学期**：先做轻量实体（名称+起止），仅用于日期选择器预填，不做业务约束。
15. **`周清` 不建模**；未排的时间段（早饭/午休等）只作为网格行存在。
16. **导入数据可弃**：现有数据过时，导入后试用，无问题后清库重录。
17. **模板管理页**：独立页面，可新建空白/从某周生成/复制/重命名/设默认/删除，并逐格编辑模板内容（只编学科，逐格即时保存）；应用部分班级的模板时用确认弹窗提示会清空其余班级。

## 4. 领域模型（定稿）

| 表 | 字段 | on_delete / 约束 |
|---|---|---|
| `Semester` | name, start_date, end_date | — |
| `Subject` | name, color, sort_order, is_active | — |
| `Teacher` | name, subject(FK), note, is_active | subject=PROTECT（一人一科） |
| `SchoolClass` | name, grade, homeroom_teacher(FK null), sort_order, is_active | homeroom=SET_NULL |
| `TimeSlot` | name, sort_order, weight(Decimal,默认1), is_active | 停用时自动删除其在所有模板中的条目 |
| `TeachingAssignment` | school_class, subject, teacher | unique(class,subject)；class=CASCADE，其余 PROTECT |
| `ScheduleTemplate` | name, note, is_default | — |
| `TemplateEntry` | template, school_class, weekday(1-7), time_slot, subject | unique(template,class,weekday,slot)；template=CASCADE |
| `CourseSession` | date, time_slot, school_class, subject, teacher(null), **weight(写入时快照)**, status, source, note | unique(date,slot,class)；历史表全部 PROTECT |
| `ScheduleLock` | locked_through(date) | 全局单行 |

约定：

- 基础资料**不做硬删除**，用 `is_active` 软停用；被引用对象由 PROTECT 兜底。
- `CourseSession.teacher` 允许为空（某 `班级×学科` 未配任课关系时生成留空并提示）。
- 提供便捷操作**「取消本班全部任课关系」**（清空该班所有 `TeachingAssignment`，之后该班全部格子手动排）。

## 5. 业务规则

- **一键排课**：选模板 + 整周日期 → 为每班每周几×每时段生成 `CourseSession`；`teacher` 取自任课关系。默认整周覆盖（二次确认），可选"仅补空"。
- **批量工具**（作用于 日期范围 × 时间段范围 × 班级范围）：清空 / 复制单日 A→B / 把某班某日改动同步到同日其他班。
- **存为模板**：范围必须恰好是完整周一~周日且周一对齐；保存全体班级、7 天全量。
- **锁定**：全局 `locked_through` 日期；该日及之前不可改删。批量操作范围与之有交集则整体拒绝（不半覆盖）。
- **统计**：按日期区间过滤 `CourseSession`；每时段一列显示**次数**，`合计 = Σ(每条记录的权重快照)`（改时间段权重不影响历史）。

## 6. 系统架构

### 6.1 后端（严格遵循 `drf-architecture-kit`）

```
backend/
├── manage.py  pyproject.toml  .env.example  .env.development
├── config/           settings.py urls.py wsgi.py asgi.py
├── common/           统一响应 renderers/response、三层异常、pagination、enums
├── authentication/   JWT login/refresh/me + 超级管理员 UserViewSet
└── timetable/
    ├── models.py serializers.py views.py urls.py apps.py
    ├── services.py          # 生成/批量/统计 的显式服务层
    └── management/commands/import_initial.py
```

配置：`IsAuthenticated`、无 Group RBAC、不开放注册、无 JWT 黑名单、开发 CORS 全开、启用 drf-spectacular、无异步任务。

硬性规范：统一 `{success,code,message,data}`；204→200；错误一律 raise；`select_related/prefetch_related` 只在 `get_queryset`；Serializer 按 action 分离；跨多表集体操作放 `services.py` 由 ViewSet 显式调用（不用信号）。

### 6.2 前端

Vue3 + Vite + TypeScript + Pinia + Vue Router + Naive UI + axios。
axios 拦截器做信封解包 + token 刷新单例锁；路由守卫拦未登录。
一个网格组件复用于排课 / 班级课表 / 教师课表。

## 7. API 概览

- 基础：`/api/semesters|subjects|teachers|classes|time-slots|teaching-assignments/`（CRUD；时间段支持批量重排）
- 模板：`/api/templates/`（含 `create-from-week`、`apply`、`{id}/duplicate`）、`/api/template-entries/`（含 `bulk`、按 `template`/`school_class` 过滤）
- 课程记录：`/api/sessions/`（按日期区间/班级/教师过滤）+ action `clear`、`copy_day`、`sync_class`、`generate_week`
- 锁定：`/api/lock/`
- 报表：`/api/reports/class-timetable/`、`teacher-timetable/`、`teacher-detail/`、`teacher-summary/`

## 8. 页面设计

登录；基础资料（学期/学科/教师/班级/时间段）；任课关系；**排课**（周网格 + 工具箱）；**模板管理**（模板列表 + 内容网格编辑 + 复制/从某周生成/应用）；班级课表；教师课表（含同学科冲突提示）；教师课时明细；教师课时汇总；锁定设置。
